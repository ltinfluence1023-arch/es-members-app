# バー店内アプリ 要件定義書

MVP 開発版 / 2026年4月（v2: 2通貨モデル対応）

---

## 1. 開発ゴール

バーの来店・会話・送金・ランキング参加を促進する Web アプリ。
お客様用と管理用を同一プロジェクトで構築。
実店舗で運用しながらランキング・ランク・CRM 機能を段階拡張する。

---

## 2. 通貨モデル（最重要）

本アプリは**2種類の店内通貨**を扱う。混同しないこと。

### 2.1 チップ (Chip)

- **換金性ゼロ**。法定通貨との交換不可。
- **使い道**: 店内交流・称号・ランキング・イベント参加権
- **取得**: チェックイン / 顧客間送金 / 管理者付与
- **会計には使えない**

### 2.2 ポイント (Point)

- **会計に使える店内通貨**（プリペイド型ではなく、店舗発行の利用ポイント）
- **使い道**: 会計支払 / クーポン交換
- **取得**: 会計還元 / ランキング報酬 / 管理者付与
- **顧客間送金は不可**（MVPでは）

### 2.3 取引履歴の分離

`chip_transactions` と `point_transactions` を完全に別テーブルで管理する。
ユーザーテーブルにも `chip_balance` と `point_balance` を別カラムで保持する。

## 4. MVP 機能要件

### 4.1 お客様用アプリ — ボトムナビ4タブ

#### タブ1: 会員トップページ (`/home`)

| 要素 | 内容 | MVP |
| --- | --- | --- |
| 保有チップ | 現在チップ残高を大きく表示 | 必須 |
| 保有ポイント | 現在ポイント残高を表示 | 必須 |
| ランク表示 | 現在のランクとアイコン | 必須 |
| マイ QR コード | 受取用 QR（時間制限あり、デフォルト5分） | 必須 |
| QR 読取ボタン | チェックイン / 送金 共用の読取画面へ | 必須 |

#### タブ2: ランキングページ (`/ranking`)

4 種類のランキングをタブ切替で表示。各ランキングは Top 50 まで。

| ランキング | 集計方法 | MVP |
| --- | --- | --- |
| 月間チップ増減 | 当月の `chip_transactions.amount` 合計 | 必須 |
| 年間チップ増減 | 当年の `chip_transactions.amount` 合計 | 必須 |
| 年間来店回数 | 当年の `visits` 件数 | 必須 |
| 総保有チップ | `users.chip_balance` 降順 | 必須 |

表示は **ニックネームのみ**。連絡先は出さない。

#### タブ3: クーポンページ (`/coupons`)

| 要素 | 内容 | MVP |
| --- | --- | --- |
| 保有クーポン一覧 | 未使用 / 使用済 / 期限切れタブ | 必須 |
| クーポン詳細 | 内容、有効期限、使用条件 | 必須 |
| 使用フロー | 「使用する」ボタン → 確認モーダル → 店員提示用画面（QR or 6桁コード） | 必須 |
| ポイント交換 | ポイントを支払ってクーポンを取得 | 必須 |
| 取得経路 | ①管理発行 ②ポイント交換 ③ランキング報酬 | 必須 |

**使用フロー詳細**:
1. 顧客が「使用する」を押す
2. 確認モーダル表示（誤操作防止）
3. 店員提示用画面に遷移（6桁コード+QR、有効2分）
4. 店員が管理画面から消し込み or 顧客QRを店舗端末で読取
5. `coupons.used_at` に記録され二重使用不可

#### タブ4: お知らせページ (`/notices`)

| 要素 | 内容 | MVP |
| --- | --- | --- |
| お知らせ一覧 | 公開済の `notices` を新着順 | 必須 |
| お知らせ詳細 | タイトル・本文・画像（任意） | 必須 |
| 既読管理 | バッジ表示（Phase2でも可） | Phase2 |

### 4.2 ハンバーガーメニュー（右上）

| 項目 | 内容 | MVP |
| --- | --- | --- |
| プロフィール | ニックネーム編集、連絡先確認、ログアウト | 必須 |
| チップ履歴 | チップの増減履歴（無限スクロール） | 必須 |
| ポイント履歴 | ポイントの増減履歴 | 必須 |
| ランク詳細 | 現在ランクと次ランクまでの条件 | 必須 |
| サービス利用規約 | 静的ページ | 必須 |
| 個人情報保護方針 | 静的ページ | 必須 |

### 4.3 管理用アプリ

| 機能 | 内容 | MVP |
| --- | --- | --- |
| 管理ログイン | 管理者/スタッフのみアクセス | 必須 |
| 顧客一覧 | 検索、チップ・ポイント残高、来店回数 | 必須 |
| 顧客詳細 | 基本情報、チップ履歴、ポイント履歴、ランク | 必須 |
| チップ付与/減算 | 理由必須 | 必須 |
| ポイント付与/減算 | 理由必須（会計還元含む） | 必須 |
| 全取引履歴 | チップ・ポイント別ログ | 必須 |
| クーポン発行 | 個別 or 一斉、有効期限・使用条件設定 | 必須 |
| クーポン消し込み | 顧客提示コードを入力して使用済化 | 必須 |
| お知らせ管理 | 投稿・編集・公開/非公開 | 必須 |
| ランク設定 | 条件・特典 | Phase2 |

## 6. データベース要件

DDL は `/docs/db-schema.sql` を参照。テーブル一覧:

- `users` — 顧客（chip_balance, point_balance を保持）
- `admin_users` — 管理者・スタッフ
- `chip_transactions` — チップ取引履歴
- `point_transactions` — ポイント取引履歴
- `visits` — 来店履歴
- `notices` — お知らせ
- `ranks` — ランク設定
- `coupon_templates` — クーポンの雛形（管理者が定義）
- `coupons` — 顧客に付与された個別クーポン
- `qr_tokens` — マイ QR / クーポン提示の短期トークン

## 10. 店舗運用マニュアル概要

- **初回来店時**: スタッフがアプリ登録を案内し、店舗 QR でチェックインしてもらう
- **チップ購入時**: 管理画面で対象会員を検索し、購入分のチップを付与
- **会計時**: 管理画面で会計額に応じたポイントを付与（還元）。顧客はポイントで会計の一部を支払うことも可能
- **顧客間送金**: 顧客同士でマイ QR を見せ合い、チップを送る
- **クーポン使用**: 顧客が提示画面を見せる → スタッフが管理画面で消込
- **ランキング訴求**: 月末に上位者を発表
- **不明点対応**: 会員番号またはニックネームで検索し履歴確認
